# 왕국 복원 중심 개발 계획

## 목표

게임의 첫인상과 장기 진행을 스킬 목록이 아니라 폐허가 된 왕국의 복원으로 구성한다. 플레이어는 왕국 화면에서 구역을 조사하고, 폐허를 정리하고, 필요한 자재를 나누어 납품한 뒤 복원 공사를 완료한다. 복원 결과로 새로운 스킬·구역·시설이 열린다.

폐허 정리와 복원 공사는 레벨이 오르는 스킬이 아니다. 둘 다 기존의 전역 액티브 작업 슬롯을 쓰는 왕국 프로젝트 활동이다. 농사와 목장은 지금처럼 별도의 패시브 진행을 유지한다.

## 확정 원칙

- 전역 액티브 작업은 생산·폐허 정리·복원 공사를 합쳐 한 번에 하나만 진행한다.
- 프로젝트는 `잠김 → 조사 가능 → 정리 중 → 자재 납품 → 복원 가능 → 복원 중 → 완료` 흐름을 따른다.
- 조사와 자재 납품은 즉시 조작이며, 폐허 정리와 복원 공사만 시간을 사용한다.
- 자재는 일부만 납품해도 누적 상태가 저장된다.
- 핵심 회수품은 결정론적으로 지급한다. 희귀 확률 보상이 없어도 프로젝트를 완료할 수 있어야 한다.
- 프로젝트는 만료·실패·손실이 없다. 다른 작업으로 바꿔도 정리와 복원 진행도는 보존된다.
- 초반 대장간 복원까지는 짧은 직선형이고, 이후에는 여러 구역 중 순서를 고를 수 있게 확장한다.
- 이전 저장은 현재 이용 가능한 기능을 잃지 않는다. 대응 시설은 완료 처리하고 보상은 중복 지급하지 않는다.
- 다중 일꾼이나 여러 스킬의 병렬 자동 생산은 추가하지 않는다. 반복·목표 수량·다음 작업 예약은 향후 편의 기능으로만 검토한다.

## 스킬 구성

- 액티브 10개: 벌목, 채광, 낚시, 야외 채집, 대장작업, 목공, 요리, 조제, 재봉, 마법.
- 패시브 2개: 농사, 목장.
- 왕국 활동: 폐허 정리, 복원 공사. 레벨과 장비 슬롯이 없는 프로젝트 행동이다.

신규 스킬은 왕국 기반이 안정된 뒤 `야외 채집 → 목공 → 조제 → 재봉` 순서로 각각 별도 기능 브랜치에서 추가한다. 콘텐츠 수치는 생산망이 모두 연결된 뒤 시뮬레이터와 플레이테스트로 조정한다.

## 첫 수직 슬라이스 — 폐허가 된 대장간

| 항목 | 초안 |
|---|---|
| 프로젝트 | 폐허가 된 대장간 |
| 조사 | 즉시, 정리 단계와 요구사항 공개 |
| 폐허 정리 | 기본 작업량 30초 |
| 확정 회수품 | 나무 3개, 돌 4개 |
| 복원 자재 | 나무 12개, 돌 10개 |
| 복원 공사 | 기본 작업량 45초 |
| 완료 효과 | 대장작업 영구 해금, 왕국 복원도 1 증가 |

신규 저장은 벌목과 채광만 열린다. 대장간을 조사·정리하고 부족한 자재를 채집해 납품한 뒤 복원하면 대장작업이 열린다. 이 흐름으로 왕국 프로젝트가 기존 생산 루프를 실제로 안내하는지 검증한다.

## 원자적 구현 순서

### 1. 기획과 상태 계약

- 이 문서와 `game_design.md`, `content_spec.md`, PROGRESS, DECISIONS를 현재 합의와 맞춘다.
- 프로젝트 데이터, 액티브 작업 판별식, 저장 v10 상태 계약을 고정한다.
- 문서 diff와 상호 참조를 확인하고 Stable 체크포인트로 보존한다.

### 2. 프로젝트 엔진과 저장 v10

- `src/content/projects.ts`에 프로젝트 정의와 첫 대장간 데이터를 추가한다.
- `currentAction`을 생산/폐허 정리/복원 공사 판별식으로 확장한다.
- 조사, 정리 시작/중지, 정리 정산, 부분 납품, 복원 시작/정산/완료, 복원도 계산을 구현한다.
- 잠긴 스킬은 생산·도구 제작·구매·패시브 조작에서 엔진 수준으로 거부한다.
- v1~v9는 모든 기존 스킬을 유지하고 대장간을 이미 완료한 상태로 이전한다. 진행 중 생산 작업과 나머지 저장 상태도 그대로 보존한다.
- 프로젝트 완료·중단·오프라인 정산·손상 저장 거부·이전 저장 보존을 단위 테스트로 검증한다.

### 3. 왕국 화면과 온보딩

- 왕국을 기본 화면으로 만들고 `폐허 / 복원 / 완료 구역` 상태가 드러나는 프로젝트 카드를 제공한다.
- 현재 작업 헤더가 생산·정리·복원 공사를 모두 올바르게 표시하고 중지할 수 있게 한다.
- 자재별 필요량·납품량·보유량과 일부 납품 조작을 표시한다.
- 잠긴 스킬은 사이드바에서 숨기고 프로젝트 완료 직후 나타나게 한다.
- 좁은 화면과 넓은 화면에서 조사→정리→납품→복원→대장작업 해금을 직접 확인한다.

## 첫 슬라이스 수용 기준

1. 신규 저장은 벌목·채광만 보이고 대장작업은 잠겨 있다.
2. 대장간 조사 후 폐허 정리를 시작할 수 있으며 생산 작업과 동시에 진행되지 않는다.
3. 정리 완료 시 회수품이 정확히 한 번 지급되고 새로고침이나 재정산으로 복제되지 않는다.
4. 나무와 돌을 여러 번 나누어 납품할 수 있고 과납품·음수·보유량 초과가 발생하지 않는다.
5. 모든 자재를 납품해야 복원 공사를 시작할 수 있다.
6. 복원 완료 시 대장작업이 영구 해금되고 복원도가 1이 된다.
7. 작업 전환, 중지, 재접속, 긴 오프라인 정산 뒤에도 진행도와 결과가 정확하다.
8. v1~v9 저장은 기존 스킬·진행 중 작업·인벤토리·농사·목장·길드·장신구·퀘스트를 잃지 않는다.
9. `npm test`, `npm run build`, `npm run simulate`, `git diff --check`가 통과하고 브라우저 상호작용과 콘솔을 확인한다.
