# 멜버라이크 왕국 재건 — 게임 기획서 (v4 왕국 복원 중심 재설계)

> [!IMPORTANT]
> 기존 프로토타입(4스킬만 구현된 상태)을 완전 재작성하기로 결정. 이 문서는 최초 구상 메모 + 재설계 논의를 통합한 기준 문서.

## 0. 핵심 방향

- **전투 없음.** 채집·가공·경영 중심 방치형.
- **엔딩은 플레이어가 스스로 정의**: 전 스킬 만렙, 도감(수집) 100% 등 완주 목표형. 완주하면 그걸로 끝 — 환생/프레스티지형 반복 루프는 넣지 않음 (아래 참고).
- **관리 피로 최소화가 최우선 설계 기준.** 이번 재설계 과정에서 반복적으로 확인된 원칙:
  - 목표 지향 파밍을 RNG로 막지 않는다 (원하는 걸 노력해서 얻는 구조 우선, "손해보는 기분" 유발 금지)
  - 능동적으로 계속 관리해야 유지되는 시스템(다중 일꾼 효율 계산, 장비 내구도 수리 등)은 지양
  - 대체 불가능한 필수 슬롯(주 도구 등)에는 랜덤성을 넣지 않는다 — 랜덤은 대체 가능하고 부담 없이 소비될 수 있는 자리에만
  - **멜버의 시그니처 시스템(스킬링 펫, 마스터리 풀 등)을 무비판적으로 가져오지 않는다.** 마스터리·펫·확률 정착민은 현재 범위에서 모두 제외하고 왕국 복원과 스킬 레벨에 집중한다.

## 1. 조작 구조

- **액티브 스킬은 한 번에 1개만 진행** (지금처럼 벌목/채광/낚시/대장작업 등 중 선택해서 직접 수행)
- **패시브 스킬(목장, 농사)은 액티브와 별개로 동시에 백그라운드 진행**
- 다중 일꾼 배치·운영(매직 리서치식)은 채택하지 않음 — 효율 최적화 압박이 관리 피로로 이어질 우려 때문

## 1.1 핵심 진행 — 왕국 복원

- 기본 화면은 스킬 목록이 아니라 폐허가 된 왕국이다. 플레이어가 복원할 구역을 고르고 필요한 생산 활동으로 자재를 마련한다.
- 구역은 `잠김 → 조사 가능 → 정리 중 → 자재 납품 → 복원 가능 → 복원 중 → 완료` 순서로 진행한다.
- **폐허 정리와 복원 공사는 스킬이 아니다.** 레벨이나 전용 장비 없이 전역 액티브 작업 슬롯을 사용한다.
- 프로젝트의 필수 회수품은 결정론적으로 지급하고, 자재는 일부씩 납품할 수 있다. 만료·실패·진행도 손실은 없다.
- 복원 결과로 스킬, 생산 구역, 시설, 레시피가 열린다. 초반은 대장간까지 안내하고 이후에는 여러 복원 순서를 선택할 수 있게 한다.
- 왕국 복원도는 반복 경험치가 아니라 완료한 프로젝트 수와 중요도로 계산한다.
- 이전 저장은 이미 쓰던 기능을 잃지 않도록 대응 시설을 완료 처리한다. 이전 과정에서 프로젝트 보상은 다시 지급하지 않는다.

## 2. 스킬 목록

### 2.1 벌목 (액티브)
- 마인크래프트처럼 벌목 시 확률적으로 묘목 드랍 → 농사 재료로 연결 (심으면 벌목 보너스로 환원되는 순환고리)
- 대장작업 재료 계열 1번(목재 계열) 공급원

### 2.2 채광 (액티브)
- 기본은 지금처럼 광물을 직접 지정해서 캐는 방식 유지 (다른 스킬과 조작 일관성 유지)
- **광맥 발견 보너스**: 멜버 아이들의 Gem Vein 참고. 채굴 중 확률적으로 "광맥 발견!" 이벤트 → 그 판에 한해 상위 광물 + 마나석(마법 재료) 추가 획득
  - 멜버처럼 노드에 HP를 부여해 리스폰 대기시간을 강제하는 방식은 **채택하지 않음** (강제 다운타임은 관리 피로 원칙에 위배)
  - 광맥 발견 확률은 **채광 레벨**로 상승 (별도 마스터리 시스템 없이 기존 레벨 재사용)
- 석탄: 전 광산 공통 드랍 (별도 탄광 없음, 대장작업이 전 티어에서 계속 필요로 하는 재료라 항상 흘러나오게)

### 2.3 낚시 (액티브)
- **낚시터 = 레벨로 해금되는 구역 리스트** (멜버처럼 탐험/지도학 없이 단순 해금). 구역마다 잡히는 어종 + 꽝(정크) 확률이 다름
- 미끼 아이템은 별도로 만들지 않고, **꽝 확률 감소는 낚시 레벨로 대체**
- 잡은 물고기 → 요리 재료

### 2.4 대장작업 (액티브)
- 채광 재료(광석+석탄류)로 주괴 제작
- 화로/용광로는 별도 건물이 아니라 **같은 대장간 건물의 레벨 구간별 명칭 변화**로 처리 (Lv1~9 화로, Lv10+ 용광로 — 기존 코드의 레벨 구간별 재료 티어 전환 로직 재사용)
- **장비 제작 담당**: 주 도구(스킬별, 결정론적) + 장신구 기본형(스킬 공통, 1개만 존재) 제작. 랜덤 부여는 마법 스킬이 담당 (§4 참고)

### 2.5 요리 (액티브)
- 낚시 어종 + 농사 작물을 소모해 **버프 음식** 제작
- 먹으면 일정 시간 동안 특정 스킬 효율 +X% — 스킬 시너지 체인의 핵심 고리
- 레시피는 초반 4~6개로 시작, 확장 가능하게 설계

### 2.6 목장 (패시브)
- **자동형 채택**: 사료를 채워두면 알아서 소비하며 아이템 생산 (쿨타임 수동 클릭 방식은 기각 — 액티브 스킬과 차별점 없고 "깜빡하면 손해" 마찰 유발)
- 동물은 **길드 의뢰가 아니라 상점에서 골드로 구매**, 목장 레벨로 구매 가능 종류 해금 (다른 스킬과 동일한 레벨게이트 패턴)
- 사료는 **농사 작물을 소비** — 농사↔목장이 서로 이어짐
- 초반엔 동물 2~3종으로 시작

### 2.7 농사 (패시브)
- 작물씨(요리 재료) / 약초씨(마법 재료) / 나무묘목(벌목 순환) 3종 유지
- 비료 3종(성장속도 / 2배확률 / 씨앗리턴)은 **구매형 소모품**으로 명확히 분리
- 구체 작물 목록 — **미정**
- 업그레이드로 자동 파종/수확 해금

### 2.8 마법 (액티브, 후반 콘텐츠)
- 채광 광맥 보너스의 마나석 + 농사 약초를 재료로 **마법부여석**을 등급별로 제작
- 마법부여석은 장신구 리롤 재료로 사용 (§4 참고) — 대장작업(물리적 제작)과 마법(랜덤 부여)으로 역할 분담
- 등급이 높은 마법부여석일수록 리롤 결과 기대치가 좋아지는 방향으로 설계

### 2.9 야외 채집 (액티브, 추가 예정)
- 섬유·수지·버섯·열매·야생 약초처럼 여러 제작 기술이 공유하는 소량 재료를 공급한다.
- 밭에서 대량 재배하는 농사와 달리 지역을 골라 자연 재료 묶음을 채집한다.

### 2.10 목공 (액티브, 추가 예정)
- 판자·들보·상자·가구·목재 부품을 만든다. 왕국 복원과 보관·농사·목장 시설의 주요 공급원이다.
- 대장작업과 역할을 나눠 금속 도구와 목조 시설의 생산망을 분명히 한다.

### 2.11 조제 (액티브, 추가 예정)
- 접착제·보존제·염료·비료·작업 보조제를 만든다. 단순 속도 물약만 반복하는 구조는 피한다.
- 버프를 자주 갈아끼우는 관리 압박이 생기지 않도록 긴 프로젝트용 소모품과 생산 재료를 중심으로 한다.

### 2.12 재봉 (액티브, 추가 예정)
- 밧줄·천·자루·침구·돛·깃발을 만든다. 목장의 양털과 야외 채집의 섬유를 함께 소비한다.
- 전투 방어구나 다중 장비 인벤토리 대신 왕국 시설과 생산 보조품을 담당한다.

### 2.13 최종 스킬 구성
- 액티브 10개: 벌목, 채광, 낚시, 야외 채집, 대장작업, 목공, 요리, 조제, 재봉, 마법.
- 패시브 2개: 농사, 목장.
- 왕국 활동 2종: 폐허 정리, 복원 공사. 스킬 수에는 포함하지 않는다.

## 3. 길드

- **가이드라인형 미션**: 완전 방생이 아니라 일일퀘스트 + 1회성 퀘스트로 방향성 제공. 완료 시 골드 + 자재로 길드 레벨업
  - 1회성 퀘스트는 **마일스톤형**(첫 레벨업, 첫 장비 제작 등)으로 설계해서 퀘스트 자체가 온보딩 가이드 역할을 겸함
- **환전소** (기존 "의뢰"의 진짜 목적): 스킬 간 레벨 격차로 인한 "손해보는 기분"을 없애는 캐치업 시스템
  - 이미 해금한 하위 티어 기본 재료는 골드로 즉시 구매 가능
  - 상위 티어 재료를 하위 티어로 환전 가능, **티어 차이가 클수록 환전 수량 보너스 증가** (예: 10단계 나무 10개 → 9단계 20개, 더 내려가면 더 많이)
  - 길드 레벨이 낮으면 1단계까지만, 레벨이 오를수록 더 깊이 환전 가능 (길드 레벨업에 실질적 쓸모 부여)
- 구체 퀘스트 목록/보상 밸런스, 환전 비율 — **미정**
- ⚠️ 네이밍 정리 필요: 기존 프로토타입의 "길드 상점"(특가 매입/판매 시장)과 이름이 겹침 → **"시장"으로 개명 추천**, "길드"는 퀘스트+환전소 전용으로

## 4. 장비 시스템

두 계층으로 구성. **주 도구는 안전하게(결정론적), 장신구는 랜덤하게** — 목표 지향 파밍과 뽑기 재미가 서로 부딪히지 않도록 역할을 분리.

### 4.1 주 도구 (스킬별, 결정론적)
- 스킬마다 고유한 도구 슬롯 하나 (벌목=도끼, 채광=곡괭이, 낚시=낚싯대, 대장작업=망치), 레벨로 해금
- 재질 티어(스톤/구리/철/금)별 고정 배율만 존재, **랜덤 옵션 없음**
- 대체 불가능한 필수 슬롯이라 랜덤을 넣으면 "레벨은 올랐는데 운이 나빠서 손해"라는 패턴이 그대로 발생 → 결정론 유지로 확정 (내구도 폐기 결정과 같은 맥락)

### 4.2 장신구 (스킬 공통, 랜덤 리롤)
- 전 스킬 공통으로 쓰는 장신구 슬롯 **3개**
- 슬롯당 아이템은 **항상 1개만 존재**. 재질(스톤/구리/철/금)은 "제작"이 아니라 **"승급"**으로 올림 — 재료만 소모하고 기존에 리롤해둔 옵션/등급은 그대로 유지 (재질 업그레이드가 손해로 느껴지지 않게)
- 다중 인스턴스가 아예 없으므로 인벤토리 스택/조합 폭발 문제가 원천적으로 발생하지 않음
- **마법부여석**(§2.8)을 장착 중인 장신구에 사용하면 그 자리에서 옵션(복수 가능)+등급을 리롤
  - 마법부여석도 재질과 동일한 4단계(스톤급/구리급/철급/금급)로 제작, 장신구의 현재 재질 티어에 맞는 등급 이상만 사용 가능
  - **장신구 재질 티어가 리롤 가능한 최대 등급의 상한을 결정**: 스톤=하급~중급, 구리=하급~상급, 철=하급~영웅, 금=하급~전설
  - 이 상한이 없으면 "저티어에서 운 좋게 최종 롤을 뽑고 재질만 승급"하는 식으로 손해 없는 승급 구조를 악용할 수 있어서, 반드시 필요한 안전장치
  - 옵션 개수를 재질별로 늘리는 방식(예: 금 재질일수록 옵션 슬롯도 증가)은 축이 하나 더 늘어나고 승급 시 "새 슬롯이 비었는지/자동 리롤되는지" 같은 애매한 케이스가 생겨서 **채택하지 않음** — 등급 상한 하나로 충분히 해결됨

## 5. 장기 목표 시스템

- 플레이어가 전 스킬 만렙, 왕국 완전 복원, 아이템·레시피 수집, 업적 달성 중 원하는 목표를 엔딩으로 정한다.
- 도감과 업적의 구체 항목·보상은 미정이다. 멜버의 펫처럼 작업 중 낮은 확률로 영구 보너스를 뽑는 구조와 이를 이름만 바꾼 정착민 시스템은 채택하지 않는다.
- 왕국 프로젝트의 필수 진행과 완주 목표는 희귀 확률에 막히지 않아야 한다.

> [!NOTE]
> **마스터리 시스템과 프레스티지는 검토 후 제외했습니다.**
> - 마스터리(항목별 숙련도+풀+체크포인트 3층 구조)는 멜버의 매우 특정한 시그니처 시스템이라 그대로 가져오면 "멜버 클론" 인상이 강해짐. 이 시스템이 해결하려던 효과는 스킬 레벨, 장비, 왕국 시설 해금으로 나눠 처리한다.
> - 프레스티지(환생)는 반물질류처럼 "리셋해서 곡선을 다시 타는 것"이 게임의 본체인 장르에는 맞지만, 우리처럼 초반부터 여러 스킬을 직접 조작하는 "바쁜" 방치형에서는 그 바쁜 구간을 반복시키는 게 피로만 가중시킴. 대신 **전체 진행 곡선(레벨 디자인) 자체를 고르게 설계하는 쪽**에 힘을 쓰기로 함.

## 6. 기술 스택 / 아키텍처

- **TypeScript + Vite + SolidJS**
  - Solid의 시그널 기반 반응성이 골드/진행바처럼 자주 갱신되는 값에 적합, 번들이 가벼움(~7.6KB)
  - Melvor 자체는 프레임워크 없는 순수 JS지만, 그 방식(수동 DOM 동기화)이 기존 프로토타입의 버그 원인 중 하나였으므로 채택하지 않음
- **콘텐츠(데이터)와 엔진(로직) 분리**: `content/*.ts`에는 순수 데이터만, `engine/*.ts`에 계산 로직
- **수식은 처음부터 점근선/클램프 구조로 설계 + Vitest로 회귀 테스트** (레벨 무한 상승 시에도 시간이 음수가 되거나 확률이 100%를 넘지 않도록 타입/함수 수준에서 강제)
- **저장 데이터는 버전 번호 + 마이그레이션 함수 체인**으로 관리 (기존의 `_v4` 같은 문자열 버전 하드코딩 방식 대체)

> [!NOTE]
> **뼈대 세팅 완료** (구 프로토타입은 `legacy/`로 이동). `src/content/`(데이터) · `src/engine/`(수식/저장/액션 로직) · `src/state/`(Solid 스토어) · `src/ui/`(컴포넌트) 구조로 분리했고, 벌목 스킬 하나를 엔드투엔드로 붙여서 검증함. `formulas.ts`의 점근선+하드캡 수식은 Vitest 회귀 테스트로 고정(레거시의 마이너스 시간/100% 초과 확률 버그 재발 방지). `npm run dev`로 실행, `npm test`로 테스트, `npm run build`로 빌드 확인 완료. 나머지 스킬은 `content_spec.md` 수치를 같은 패턴으로 추가하면 됨.
>
> **플레이테스트로 발견/수정한 버그**: 처음엔 진행바/완료 판정을 `requestAnimationFrame` 하나로 돌렸는데, 실제로 브라우저에서 돌려보니 탭이 활성 렌더링 중이 아닐 때 rAF가 전혀 발화하지 않아 진행 자체가 멈추는 문제가 있었음(직접 카운터로 rAF 0회 vs setInterval 정상 발화를 확인해서 원인 특정). 방치형 게임은 탭을 배경에 둔 채 돌아가는 게 기본 사용 패턴이라 치명적 — `src/state/clock.ts` + `src/engine/gameLoop.ts`로 setInterval 기반 전역 틱으로 교체해서 해결. 스킬 뷰마다 개별 루프를 두지 않고 전역 루프 하나로 통일해서, 앞으로 스킬이 늘어나도 폴링 루프가 늘어나지 않게 함.
