# 구현 현황 — 왕국 복원 다섯 번째 구역: 버려진 밭 (2026-09-16)

## 실제 구현
- **왕국 복원 첫 수직 슬라이스(대장간)**: 기본 화면을 왕국으로 전환하고, 폐허가 된 대장간의 조사→30초 정리→확정 회수품(나무 3/돌 4)→부분 자재 납품(나무 12/돌 10)→45초 복원→대장작업·도구 제작 해금을 구현했다. 폐허 정리와 복원은 스킬 레벨 없이 생산과 같은 전역 액티브 슬롯을 쓰며, 다른 작업으로 전환해도 프로젝트 진행도는 보존된다. 왕국 화면은 폐허 회수/복원/완료 구역으로 상태를 나누고 새 게임 사이드바에는 벌목·채광과 공용 화면만 표시한다.
- **왕국 복원 두 번째 구역(부서진 다리)**: 대장간과 동일한 조사→정리(40초, 확정 회수품 나무 4/돌 2)→부분 자재 납품(나무 10/벽돌 6)→복원(60초)→낚시 영구 해금·복원도 2 패턴을 재사용해 구현했다. 납품 자재에 벽돌(대장작업 산출물)을 포함시켜 대장간을 먼저 끝내야 실제로 완료할 수 있게 자연히 유도한다. `ProjectDef.introducedVersion`으로 저장 검증이 "이 저장 버전에 등장해야 할 구역 집합"을 동적으로 계산한다. `KingdomView.tsx`의 완료/복원 힌트 문구를 프로젝트별 하드코딩에서 `unlockSkills`/`unlockFeatures` 기반으로 일반화했다. 상세 근거는 DECISIONS.md D020 참고.
- **왕국 복원 세 번째 구역(무너진 식당)**: 위 패턴을 그대로 재사용해 조사→정리(50초, 확정 회수품 나무 5/돌 3)→부분 자재 납품(나무 12/피라미 8)→복원(70초)→요리 영구 해금·복원도 3을 구현했다. 피라미(낚시 산출물)를 납품 자재에 넣어 다리를 먼저 끝내야 유도되게 한 것도 다리가 벽돌로 대장간을 유도한 것과 동일한 설계. **엔진(`model.ts`)·UI(`KingdomView.tsx`) 코드는 한 줄도 바뀌지 않았고**, 콘텐츠 항목 추가 + 저장 버전 배열 확장(v11→v12)만으로 끝났다 — `introducedVersion` 기반 검증과 문구 일반화가 실제로 반복 재사용됨을 확인. 상세 근거는 DECISIONS.md D021 참고.
- **왕국 복원 네 번째 구역(먼지 쌓인 길드 회관)**: 위 패턴을 다시 재사용해 조사→정리(60초, 확정 회수품 나무 6/돌 4)→부분 자재 납품(나무 14/구운 생선 5)→복원(80초)→`guild` 기능 영구 해금·복원도 4를 구현했다. 이번엔 **새 스킬이 아니라 이미 구현·병합돼 있었지만 어떤 프로젝트도 부여하지 않아 신규 저장에서 도달 불가능했던 기존 기능(`guild`)을 처음으로 연결**한 사례다(`unlockSkills: []`, `unlockFeatures: ['guild']`). 구운 생선(요리 산출물)을 납품 자재에 넣어 식당을 먼저 끝내야 유도되게 한 것도 동일한 설계. 엔진·UI 코드는 이번에도 한 줄도 바뀌지 않았다. 상세 근거는 DECISIONS.md D022 참고.
- **왕국 복원 다섯 번째 구역(버려진 밭)**: 위 패턴을 다시 재사용해 조사→정리(70초, 확정 회수품 나무 7/돌 5)→부분 자재 납품(나무 16/돌 12)→복원(90초)→농사 영구 해금·복원도 5를 구현했다. 이번엔 **재료 의존 체인이 처음으로 끊겼다** — 직전 구역(길드 회관)은 서비스형 기능(`guild`)만 열어 재사용할 채집·가공 산출물이 없어서, 첫 구역(대장간)과 같은 나무·돌 자재로 되돌아갔다. 엔진·UI 코드는 이번에도 한 줄도 바뀌지 않았고, D022가 남긴 "모든 낮은-버전 마이그레이션 테스트에서 새 프로젝트 키 삭제 확인" 체크리스트를 구현 착수 시점에 미리 적용해 처음부터 깨뜨리지 않고 통과시켰다. 다섯 구역 모두 처음부터 함께 조사 가능 상태로 노출된다(구역 간 하드 선행조건 없음, D020/D021/D022/D023). 상세 근거는 DECISIONS.md D023 참고.
- **성장 곡선 CLI**: `npm run simulate`가 실제 `ResourceDB`, 도구 티어, 엔진과 공유하는 레벨 경험치·속도 공식을 사용해 8개 스킬의 Lv10·30·50·99 도달 시간과 모든 자원의 시간당 생산·경험치·총 판매가를 Markdown 표로 출력한다. 무도구/해금 도구/도구+속도 음식 10%/도구+음식+경험치 18%의 네 시나리오를 비교한다. 실제 레시피와 도구 비용을 재귀적으로 펼쳐 필요한 원재료·가공 횟수·스킬별 작업 시간을 계산하는 초반 생산 경로도 함께 출력한다. 레벨 보고서는 가공 입력과 도구 제작 비용을 무한 공급으로 가정한 스킬 자체 기준선이며 실제 완주 시간은 아니다. `docs/progression_analysis.md`에 첫 결과와 조정 순서를 기록했다.
- 벌목, 채광, 벽돌·구리/철/금 주괴 제작, 재료 보관 및 1개/10개 판매.
- 낚시터 3곳: 마을 개울(피라미 Lv1), 갈대 호수(붕어 Lv10), 상류 여울(연어 Lv30).
- 요리 8종: 생선 3종(구운 생선 낚시+10%/10분, 민물 생선탕 벌목·채광·낚시+5%/15분, 훈제 연어 대장작업+15%/15분) + 농사·목장 재료 5종(야채죽/나무꾼 도시락/광부의 스튜/대장장이 정식/축제 요리).
- 스킬별 돌/구리/철 도구 제작 및 즉시 적용. 낚싯대·조리도구·괭이·사료통·마법봉 포함.
- 음식은 한 종류만 적용. 같은 음식 1개/5개 사용 시 지속시간 연장. 다른 음식은 UI에서 남은 효과 폐기 안내 후 교체. 자동 섭취는 없음.
- 전체 화면에서 현재 작업, 진행률, 음식 효과, 밭·목장 상태와 남은 시간 표시.
- 순수 데이터 엔진으로 경과 시간 일괄 정산. 음식 만료 전후를 구분해 계산하며 재료 부족 시 제작 중단.
- **농사(패시브) 최소 루프**: 작물 3종(밀 Lv1, 감자 Lv10, 당근 Lv25)을 골드로 구매 → 밭 1칸에 파종(씨앗 1개 소모) → 액티브 작업·화면 이동·접속 종료와 무관하게 경과 시간만큼 성장 → 다 자라면 수확 버튼으로 같은 작물 3개 회수 + 농사 경험치. 다 자란 뒤에는 수확 전까지 더 진행되지 않는다. 신규 저장에서는 버려진 밭 복원을 마쳐야 농사가 해금된다(왕국 복원 다섯 번째 구역).
- **목장(패시브) 최소 루프**: 동물 3종(닭 Lv1/500G, 양 Lv15/2,000G, 소 Lv30/5,000G)을 골드로 구매하면 즉시 사육 시작(영구). 사료(닭·양=밀, 소=당근)가 있으면 접속 여부와 무관하게 주기마다(30/45/60분) 자동 산출·사료 소비. 사료 부족 시 주기 1회분에서 대기, 채우면 즉시 재개.
- 농사·목장 → 요리 연결: 감자·당근·달걀·우유를 재료로 쓰는 요리 5종. "전 스킬" 효과는 패시브 스킬(농사/목장)에도 그대로 적용됨.
- **길드 — 원재료 구매/환전**:
  - 원재료 구매: 가공품(recipe 있는 아이템)이 아닌 모든 아이템(나무/돌/광석/생선/작물/축산물)을 스킬 레벨로 이미 해금했다면 골드로 즉시 구매 가능(`buy` 가격, 판매가의 5배). 기존 농사 "씨앗 구매"도 동일 함수 사용으로 통합(`buyCrop`→`buyResource` 일반화, 스킬 레벨 검증을 엔진 단에도 추가 — 이전엔 UI에서만 막고 있었음).
  - 원재료 환전: 상위 티어 원재료(참나무/단단한나무/마법나무/철광석/붕어/연어)를 같은 스킬의 최하위(Lv1) 재료로 환전. 티어 차이 1단계당 1.5배씩 복리(내림) 적용 — 예: 단단한나무(2단계 차이) 4개 → 나무 9개.
  - 길드 등급: 3단계(초급→중급 3,000G→상급 15,000G, 골드만 소모). 등급이 오를수록 환전 가능한 티어 차이가 늘어남(1→2→3단계). 길드 레벨업은 후원(골드 지불)으로 단순화했고 일일 퀘스트는 아래 규칙으로 구현했다.
  - 순환 거래 방지: 환전은 항상 스킬 최하위 재료로만 향하고(역방향 경로 없음), 모든 환전 항목이 "환전 후 되팔기"가 "직접 팔기"보다 항상 손해가 되도록 설계·테스트됨.
  - 상세 설계 근거는 DECISIONS.md D010 참고.
  - **일일 퀘스트**: 매일(UTC 날짜 기준) 이미 해금한 원재료 중에서 중복 없이 3개를 뽑아 "N개 납품" 퀘스트로 갱신한다(완료 여부와 무관하게 다음 날 교체, 이월/연체 없음). 완료 시 인벤토리에서 소모하고, 판매가의 2배에 판매가 장신구 보너스를 반영한 금액을 골드로 보상한다(`sell()`과 같은 규칙, `dailyQuestReward()`로 엔진·화면이 공유). 완료 확인은 인덱스뿐 아니라 화면에 표시된 재료 id도 함께 맞춰봐서, 날짜 경계에 클릭이 겹쳐 퀘스트가 통째로 갱신돼도 다른 퀘스트를 잘못 완료하지 않는다. 원안(game_design.md §3)의 "골드 + 길드 경험치" 보상은 별도 화폐를 새로 만들지 않고 골드로만 단순화(D010의 길드 레벨업 단순화와 같은 방향). 퀘스트 내용은 `Math.random()`이 아니라 날짜 id를 시드로 한 결정론적 의사난수로 생성되어, 같은 날·같은 해금 상태면 항상 같은 퀘스트가 나온다(이 프로젝트의 다른 시간 정산과 동일한 결정론 원칙 — 시간이 거슬러 온 호출에서도 생산 정산 시계와 같은 날짜 기준을 쓴다). 후보를 뽑을 때마다 풀에서 제거해 난수값이 반복돼도 생성이 유한하게 끝난다. 이전 저장(v1~v7) 마이그레이션은 스킬을 복원한 뒤에 실제 레벨로 퀘스트를 다시 뽑으며, v8 저장은 정확히 3개·수량 5~15개·현재 레벨에서 해금된 원재료만 허용한다. 상세 근거와 독립 리뷰에서 발견·수정한 내용은 DECISIONS.md D015 참고.
  - **마일스톤 퀘스트**: 현재 시스템으로 판별 가능한 온보딩 목표 9개를 기획 순서대로 길드 화면에 표시한다. 레벨·도구·스킬 경험치·목장 보유 상태에서 달성을 계산하고 수령한 id만 저장하며, 첫 환전만 성공 시 별도 영구 플래그를 남긴다. 미달성/수령 가능/수령 완료를 구분하고, 달성한 목표의 고정 골드는 직접 한 번만 수령할 수 있다. 도감(정착민) 첫 등록 목표는 시스템이 미승인·미구현이라 제외했다. 상세 근거는 DECISIONS.md D016 참고.
- **마법부여·장신구**:
  - 공급 루프: 농사 약초 4종(캐모마일/쑥/마법쑥/신비 허브), 채광 마나석·금 광석, 대장작업 금 주괴를 재료로 마법 스킬에서 스톤/구리/철/금급 마법부여석 제작.
  - 공용 장신구 3슬롯(개척자의 왕관/장인의 목걸이/풍요의 반지). 슬롯마다 하나만 스톤 재질로 제작하며 구리→철→금으로 승급. 승급은 기존 옵션과 희귀도를 그대로 유지한다.
  - 리롤: 현재 장신구 재질 이상 등급의 마법부여석 1개를 사용해 옵션 1개(전 스킬 속도/경험치/판매가)와 희귀도(하급~전설)를 교체. 재질 상한 밖 희귀도는 확률 풀에서 제외하고 나머지를 재정규화한다.
  - 장신구 효과는 시간 정산·경험치·판매 엔진에 적용되며 세 슬롯 효과는 합산한다. 확률은 사용자 리롤 순간에만 사용하므로 온라인/오프라인 생산 정산은 결정론을 유지한다.
  - 비용/옵션 수치와 직접 채광 마나석은 임시 설계. 상세 근거는 DECISIONS.md D011 참고.
- **세이브 백업/복원**: 설정 화면에서 현재 저장 전체를 JSON 파일로 내려받거나 클립보드에 복사할 수 있고(다운로드 시 브라우저가 저장 위치를 물어보는 대화상자는 브라우저 자체 동작이라 앱에서 제어할 수 없어 클립보드 복사를 대안으로 제공), 파일을 선택해 저장을 되돌릴 수 있다. 복원 전 확인을 거치며, `decodeSave`로 먼저 검증에 성공한 파일만 적용된다(버전·형식이 잘못된 파일은 기존 저장을 건드리지 않고 오류 메시지만 표시). 저장 손상으로 자동 저장이 중단된 상태(`blocked`)도 유효한 백업을 복원하면 자동 저장이 다시 시작된다. 복원은 `advance()`로 백업 시점 이후 경과 시간을 정산해 밀린 생산을 안내에 반영한다. 저장에는 체크섬(FNV-1a, 키 정렬 후 해시)이 함께 저장되어 값을 하나라도 바꾼 뒤 그대로 복원을 시도하면 거부된다 — 단, 암호학적 보안이 아니라 텍스트 편집기로 값을 슬쩍 바꾸는 것을 막는 수준의 마찰이며, 체크섬이 없던 v7 이전 저장은 그대로 허용된다(하위 호환). 체크섬 추가 자체는 저장 버전을 올리지 않았고, 현재 저장 스키마는 왕국 프로젝트(대장간·다리·식당·길드 회관·밭) 상태 추가로 v14이다. 설계 근거는 DECISIONS.md D012·D013 참고.
- **다중 탭 저장 충돌 방지**: `src/state/gameState.ts`에 `storage` 이벤트 리스너를 추가했다. 다른 탭이 저장(localStorage의 `melvorlike_save` 키)을 갱신하면 — 이 이벤트는 값을 쓴 탭 자신에게는 발생하지 않고 다른 탭에서만 발생한다 — 받는 탭이 `document.visibilityState`로 자신이 보이는 탭인지 확인한다. 보이지 않는(방치된) 탭만 `decodeSave`로 검증 후 `advance()`로 경과 시간을 정산해 그 내용을 자신의 상태로 즉시 반영하며, 저장 손상으로 자동 저장이 막힌(blocked) 탭이었다면 함께 복구된다. 보이는(사용 중인) 탭은 그 값을 받아들이지 않고 대신 자신의 현재 상태를 즉시 다시 저장해 되찾는다(blocked 상태면 저장이 그대로 무시되어 손상 보호도 유지됨). 이 구분이 없던 1차 구현은 독립 리뷰에서 반대 방향 문제(방치된 탭의 오래된 자동 저장이 사용 중인 탭의 최신 조작을 덮어쓸 수 있음, 특히 탭을 전환하는 순간의 `visibilitychange` 플러시와 겹쳐 실제로 자주 발생 가능)가 발견되어 이 방향 구분을 추가했다. 완전한 동시 편집 병합(진짜 멀티탭 지원)은 아니며 "어느 방향이든 조용한 덮어쓰기 방지"가 목적이다. 설계 근거와 검토한 대안(리더 선출 방식, `lastSaveTime`/`hasFocus()` 비교 방식)은 DECISIONS.md D014 참고.

## 임시 밸런스 및 기획과 차이
- 구리는 채광/제련 Lv1, 철은 Lv10 해금. 주괴 연료는 현재 목재. 석탄 보너스/광맥은 미구현.
- 다음 레벨 경험치: 100 × 1.12^(레벨-1), 최대 레벨 99.
- 도구는 돌 +15%, 구리 +35%, 철 +65% 작업 속도. 농사·목장 도구도 같은 표를 재사용.
- 음식과 도구의 속도 보너스는 합산. 속도가 변해도 작업/밭/목장 진행률은 보존.
- 오프라인 시간 상한은 현재 없음.
- 낚시는 우선 확정 획득. 꽝/미끼 시스템 없음.
- 농사 씨앗은 "구매 = 파종 재료" 하나의 아이템. 밭은 1칸만 존재. 목장은 동물종당 1마리만.
- 길드 환전은 항상 "그 스킬의 Lv1 재료"로만 향함(예: 철광석→돌, 구리광석 아님). 임의의 두 티어 사이 환전(예: 단단한나무→참나무)은 미구현 — content_spec.md의 N×N 환전표 대신 단순화된 "최하위로 수렴" 규칙.
- 길드 레벨업은 퀘스트가 아닌 골드 후원으로 단순화(기획서는 퀘스트+자재 소모). 일일·마일스톤 퀘스트 보상은 골드 전용(길드 경험치 별도 화폐 없음). 마일스톤 엔진·저장·길드 화면 연결까지 구현됐다.
- 새 게임은 벌목·채광만 표시하며 대장간 복원으로 대장작업과 도구 제작이, 다리 복원으로 낚시가, 식당 복원으로 요리가, 길드 회관 복원으로 길드(환전·일일 퀘스트·마일스톤)가, 밭 복원으로 농사가 열린다. 목장·마법을 여는 후속 왕국 구역(낡은 축사/쓰러진 마법탑)은 아직 없다. 이전 저장은 기존 접근 권한을 모두 유지한다.
- 마법부여석 재료인 마나석은 광맥 발견 이벤트가 아직 없어 채광 Lv30 직접 자원으로 임시 제공. 장신구 옵션은 슬롯당 1개이며 세 슬롯이 같은 옵션 풀을 공유한다.
- 장신구 제작/승급 비용과 옵션 수치는 플레이테스트 전 임시값. 상한을 넘는 희귀도 확률을 버리지 않고 남은 가중치로 재정규화한다.

## 미구현
대장간·다리·식당·길드 회관·밭 이후 왕국 복원 구역(낡은 축사/쓰러진 마법탑), 신규 액티브 스킬 4종(야외 채집/목공/조제/재봉), 장신구 다중 옵션/고유 옵션 풀, 광맥/석탄, 업적·수집 목표, 레벨 해금·보유 재화·패시브 일정을 합친 전체 진행 경로 시뮬레이션, 계정 기반 클라우드 저장 동기화, 농사 비료·다중 플롯·단일 슬롯 편의 기능, 목장 마릿수 상한·비료류 보조 아이템, 경험치 배율형 음식 효과(달걀찜). 확률 정착민과 병렬 자동 채집 장치는 기획에서 제외됐다(D018). 왕국 구역 간 하드 선행조건(잠금) 시스템도 아직 없다 — 지금은 재료 의존성으로만 순서를 유도하며, 서비스형 기능 뒤에는 이 체인이 자연히 끊긴다(D020/D021/D022/D023). 해금 목록의 반대 방향 저장 검증(모든 unlockedSkills/Features가 시작 스킬이거나 완료된 프로젝트로 설명 가능해야 함)도 보류 중 — 목장/마법을 여는 구역이 전부 구현된 뒤 재검토(D021/D022).
기획서의 확정 표현과 별개로, 제안만 된 기능과 수치는 추가 검토 대상.
