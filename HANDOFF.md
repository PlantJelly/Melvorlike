- Completed: `src/engine/model.ts` adds `Model.dailyQuests` (save v7→v8) — each real UTC day, 3 "deliver N of an already-unlocked resource" quests are generated by a day-seeded deterministic PRNG (not `Math.random()`, for the same online/offline-equivalence reason every other timed system in this codebase is deterministic) and swapped out the next day regardless of completion, no penalty. Completing one (`completeDailyQuest`) spends the amount and pays gold via a shared `dailyQuestReward()` (sell price × 2 × the player's sale-accessory bonus, matching `sell()`'s own rule) used by both the engine and `GuildView`'s reward preview. Reward is gold-only, not the design doc's literal "gold + guild exp" — no new currency, consistent with guild leveling already being a flat gold cost (D010). Design rationale is DECISIONS D015.
- Review: one round via the code-review skill (high effort, 8 finder angles) found 8 items, all fixed. The two serious ones: (1) migrating a pre-v8 save generated the initial quest pool from `initial()`'s default level-1 skills *before* the save's real skill levels were restored a few lines later, so a high-level player's post-migration quests were silently restricted to level-1 resources until the next day — fixed by regenerating quests right after skill restoration. (2) the reward formula omitted the sale-accessory bonus `sell()` already applies — fixed via the shared `dailyQuestReward()` helper mentioned above (which also closed a related UI/engine reward-preview-drift finding). Also fixed: quest completion now checks the rendered `resourceId` in addition to array index, closing a narrow race where a day-rollover mid-click could complete the wrong quest; the day-rollover check now keys off the already-clamped `s.lastSaveTime` instead of the raw (possibly backward) `time` argument; `decodeSave` now rejects duplicate `resourceId`s across a save's quest slots. Two non-blocking findings left deliberately unfixed (documented in DECISIONS D015's caution: quest-pool determinism depends on `ResourceDB`'s current iteration order, which isn't version-pinned against future content edits; the custom xorshift32 PRNG is more machinery than strictly necessary but has no known defect).
