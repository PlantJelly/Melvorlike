- Checkpoint type: Stable. This is not a content addition — it's a `save.ts` validation-logic change with no new schema fields (`Model.version` unchanged, still 16).
- What was added: after the existing per-project (forward-direction) validation loop in `decodeSave`, a new block computes the full set of skills/features actually explainable by starter access or a completed project (iterating `projectIds` without any version filter, since `s.projects` for not-yet-introduced projects always carries `initial()`'s incomplete default), then rejects the save if `unlockedSkills`/`unlockedFeatures` contains anything outside that set.
- The gap this closes: the existing forward check only runs over `projectIdsAtVersion` (projects introduced at or before that save's version). A not-yet-introduced project's skills/features were never checked against the save at all — so a v14 save (where `fallen_tower`, `introducedVersion: 16`, isn't even a validation target) could have `'magic'` injected into `unlockedSkills` undetected, as long as the checksum was recomputed after editing (the checksum is a plain FNV-1a hash baked into client code, not a keyed HMAC — documented as friction, not cryptographic security, per D012/D013 and README).
- Safety verification performed (not just theoretical): several other test files (`food.test.ts`, `guild-quest.test.ts`, `accessory.test.ts`, `milestone.test.ts`, `save.test.ts`) round-trip `unlockedGame()`-based states through `decodeSave(encodeSave(...))` at the *ambient* current version (>=10) without pinning a lower version — this is exactly the class of usage that broke ~10 tests when D020 first attempted this check (back when only 2 kingdom projects existed, so cooking/farming/ranching/magic had no project to explain them). `unlockedGame()` marks *every defined project* complete via `projectStates(true)`, so now that all 7 districts exist and collectively grant every non-starter skill/feature, this union exactly equals `playable`/`featureIds`. Ran the full suite to confirm empirically rather than relying on this argument alone: **131/131 pre-existing tests passed unchanged** (zero regressions).
