# 왕국 재건

전투 없는 채집·제작 방치형 게임. 폐허를 정리하고 자재를 납품해 왕국의 생산 기술과 시설을 되찾는 흐름을 개발하고 있습니다.

## 실행

- 의존성 설치: `npm install`
- 개발 서버: `npm run dev`
- 테스트: `npm test`
- 배포용 빌드: `npm run build`
- 성장 곡선 보고서: `npm run simulate`

성장 곡선 보고서는 실제 콘텐츠와 경험치 공식을 읽어 각 스킬의 Lv10·30·50·99 도달 시간, 자원별 시간당 효율, 초반 도구와 요리의 재료 생산 경로를 Markdown 표로 출력합니다. 레벨 보고서는 가공 재료와 도구 제작 비용이 즉시 공급된다고 가정하므로 스킬 자체의 속도를 비교하는 기준표로 사용합니다.

## 첫 목표

왕국 화면에서 폐허가 된 대장간 조사 → 30초 동안 폐허 정리 → 회수품과 벌목·채광으로 나무 12개, 돌 10개 부분 납품 → 45초 복원 공사.
복원을 마치면 대장작업과 도구 제작이 영구 해금되고 왕국 복원도가 1 오릅니다. 폐허 정리와 복원 공사는 생산과 같은 작업 슬롯을 사용하며, 다른 작업으로 전환해도 진행률과 납품량이 보존됩니다.

왕국 화면에는 부서진 다리·무너진 식당·먼지 쌓인 길드 회관·버려진 밭·낡은 축사·쓰러진 마법탑·무성해진 숲길도 처음부터 함께 나타납니다. 다리는 같은 방식(조사 → 40초 정리 → 나무 10개·벽돌 6개 납품 → 60초 복원)으로 낚시를, 식당은(조사 → 50초 정리 → 나무 12개·피라미 8개 납품 → 70초 복원)으로 요리를, 길드 회관은(조사 → 60초 정리 → 나무 14개·구운 생선 5개 납품 → 80초 복원)으로 길드 환전·퀘스트를, 밭은(조사 → 70초 정리 → 나무 16개·돌 12개 납품 → 90초 복원)으로 농사를, 축사는(조사 → 80초 정리 → 나무 18개·밀 10개 납품 → 100초 복원)으로 목장을, 마법탑은(조사 → 90초 정리 → 나무 20개·양털 12개 납품 → 110초 복원)으로 마법과 장신구 화면을, 숲길은(조사 → 100초 정리 → 나무 22개·스톤급 마법부여석 6개 납품 → 120초 복원)으로 채집을 각각 엽니다. 구역 사이에 강제 순서는 없지만, 벽돌은 대장작업 산출물·피라미는 낚시 산출물·구운 생선은 요리 산출물·밀은 농사 산출물·양털은 목장 산출물·스톤급 마법부여석은 마법 산출물이라 대장간 → 다리 → 식당 → 밭 → 축사 → 마법탑 순서로 먼저 끝내야 각 납품을 실제로 완료할 수 있습니다(길드 회관은 서비스형 기능만 열어 산출물이 없고, 밭도 나무·돌만 사용해 이 순서 유도 밖에 있습니다). 계획된 왕국 구역 7개가 모두 구현된 뒤, 신규 액티브 스킬 4종(야외 채집/목공/조제/재봉) 중 첫 번째인 채집이 여덟 번째 구역(무성해진 숲길)으로 추가됐습니다 — 나머지 세 스킬은 아직 구현되지 않았습니다.

## 구조

- `src/content`: 아이템, 레시피, 도구, 왕국 프로젝트 데이터
- `src/engine/model.ts`: UI와 분리된 생산·시간 정산·거래 로직
- `src/engine/save.ts`: 저장 검증/이전 버전 변환
- `src/state`: 화면 상태와 저장 연결
- `docs/implementation_status.md`: 실제 구현 범위와 임시 밸런스
- `legacy`: 원본 프로토타입 보존

현재 저장 형식은 v17이며 스킬·시설 해금, 왕국 프로젝트(대장간·다리·식당·길드 회관·밭·축사·마법탑·숲길) 단계와 진행률, 부분 납품량을 포함합니다. v10(대장간만)→v11(+다리)→v12(+식당)→v13(+길드 회관)→v14(+밭)→v15(+축사)→v16(+마법탑)→v17(+숲길) 순서로 이전할 때마다 이미 진행한 구역은 그대로 보존되고 새로 추가되는 구역만 미시작으로 나타나며, v1~v9(왕국 시스템 자체가 없던 저장)는 기존 진행을 유지하고 여덟 구역을 모두 완료한 상태로 이전합니다 — 어느 경우든 회수품을 중복 지급하지 않습니다.

저장은 브라우저별 로컬 저장소에 보관합니다. 같은 브라우저에서 여러 탭을 열어두면 한 탭의 저장 변경을 다른 탭도 감지해 반영하므로, 오래 방치된 탭의 자동 저장이 최신 진행 상황을 조용히 덮어쓰는 일은 방지됩니다. 다만 이는 그 조용한 덮어쓰기를 막는 것이며, 두 탭에서 동시에 서로 다른 조작을 하는 것까지 정확히 병합해주는 완전한 동시 플레이 지원은 아닙니다.

## 낚시와 요리

낚시에서 피라미 2개 채집 → 요리에서 구운 생선 제작 → 1개 먹기 → 낚시로 돌아가 속도 증가 확인.
같은 음식은 5개를 한 번에 사용해 시간을 늘릴 수 있습니다. 음식 효과는 한 종류만 유지되며, 다른 음식으로 바꾸기 전 교체 안내가 표시됩니다.
작업하지 않거나 접속을 종료해도 음식 지속시간은 흐릅니다. 다시 접속하면 만료 시점 전후로 나눠 생산량을 정산합니다.

## 농사

씨앗을 골드로 구매 → 밭에 심기 → 접속 여부와 무관하게 성장 → 다 자라면 수확. 수확하면 같은 작물이 여러 개 돌아와 재파종분을 남기고 남는 것은 판매하거나 요리 재료로 씁니다.
밭은 한 번에 하나만 운영되며, 다른 화면에 있거나 액티브 작업(벌목 등) 중이어도 동시에 계속 자랍니다. 다 자란 뒤에는 수확 전까지 더 진행되지 않습니다.

## 목장

동물을 골드로 구매하면 그때부터 계속 사육됩니다. 사료(밀·당근, 농사에서 얻음)가 있으면 접속 여부와 무관하게 주기마다 자동으로 산출물을 만들고 사료를 소비합니다.
사료가 떨어지면 손해 없이 대기하고, 다시 채우면 바로 재개됩니다 — 수확처럼 따로 누르는 동작은 없습니다. 여러 동물을 동시에 사육할 수 있고 각자 독립적으로 진행됩니다.

## 농사·목장을 쓰는 요리

기존 생선 요리에 더해, 감자·당근(농사)과 달걀·우유(목장)를 재료로 쓰는 요리 5종이 있습니다: 야채죽(전 스킬 +5%), 나무꾼 도시락(벌목 +15%), 광부의 스튜(채광 +15%), 대장장이 정식(대장작업 +15%), 축제 요리(전 스킬 +10%, 최상위 레시피).
"전 스킬" 효과는 농사·목장처럼 화면 뒤에서 진행되는 작업에도 그대로 적용됩니다.

## 길드

이미 해금한 원재료(가공품 제외)는 골드로 즉시 구매할 수 있습니다. 상위 티어 원재료가 남아돌면 같은 스킬의 최하위(Lv1) 재료로 환전할 수 있고, 티어 차이가 클수록 받는 수량이 늘어납니다(1.5배씩 복리).
환전 가능한 티어 차이는 길드 등급에 따라 늘어나며, 길드는 골드를 내고 승급합니다. 환전은 항상 하위 티어로만 가능해 순환 거래로 이득을 볼 수 없습니다.

매일 이미 해금한 원재료 중 3종을 대상으로 "N개 납품" 일일 퀘스트가 자동으로 갱신됩니다. 완료하면 판매가의 2배를 골드로 보상받고, 완료하지 않아도 다음 날 그냥 새 퀘스트로 바뀌며 손해는 없습니다.

마일스톤 퀘스트는 첫 채집·첫 도구·첫 요리처럼 왕국의 주요 기능을 한 번씩 경험하도록 안내합니다. 현재 시스템으로 판별 가능한 9개 목표가 있으며, 달성한 목표의 고정 골드 보상은 한 번만 직접 수령할 수 있습니다. 기존 저장의 레벨·도구·경험치·목장 진행도도 반영됩니다.

## 마법부여와 장신구

농사에서 약초를 기르고 채광에서 마나석을 얻은 뒤, 마법 스킬에서 네 등급의 마법부여석을 제작할 수 있습니다. 장신구 화면에는 공용 슬롯 3개가 있으며 각 장신구는 하나만 제작해 스톤→구리→철→금 재질로 승급합니다.
마법부여석 1개를 사용하면 전 스킬 속도·경험치·판매가 중 하나와 희귀도가 새로 정해집니다. 장신구 재질이 희귀도 상한을 결정하고, 현재 재질보다 낮은 등급의 부여석은 사용할 수 없습니다. 재질을 승급해도 기존 옵션은 유지됩니다.

## 설정

설정 화면에서 현재 저장을 JSON 파일로 내려받거나 클립보드에 복사할 수 있고(백업), 내려받은 파일로 저장을 되돌릴 수 있습니다(복원).
복원은 현재 저장을 덮어쓰므로 확인을 거치며, 형식이 올바르지 않거나 지원하지 않는 버전의 파일은 적용되지 않고 오류만 표시됩니다.
저장 데이터가 손상되어 자동 저장이 멈춘 경우에도 백업 파일로 복원하면 정상 저장이 다시 시작됩니다.
백업에는 체크섬이 함께 저장되어 파일을 직접 편집해 값을 바꾼 뒤 복원을 시도하면 거부됩니다 — 다만 이건 부주의한 편집을 막는 수준이며 암호학적으로 조작을 막는 기능은 아닙니다.

## Development Workflow

공통 작업 규칙은 [AGENTS.md](AGENTS.md), Claude 진입점은 [CLAUDE.md](CLAUDE.md)입니다. 재개 시 [HANDOFF.md](HANDOFF.md), 전체 진행은 [PROGRESS.md](PROGRESS.md), 주요 결정은 [DECISIONS.md](DECISIONS.md)를 확인합니다.

- 기능 브랜치에서 의미 있는 작업 단위마다 테스트·문서 갱신·커밋·푸시·원격 확인을 진행합니다.
- `/checkpoint`: 현재 작업의 의미 있는 저장 지점을 만든 뒤 계속 진행.
- `/handoff`: 미완성 상태도 정확히 보존하고 종료.
- `/review`: 전체 기능 변경을 특정 커밋 기준으로 독립 검토.
- `/merge`: 명시적 요청과 검토/검증 조건을 충족할 때만 main 통합.

위 표기는 자연어 요청의 별칭입니다. 앱에 등록된 명령이나 백그라운드 자동 저장 기능은 아니며, 별도 훅/서비스 설치 없이 동작합니다.
